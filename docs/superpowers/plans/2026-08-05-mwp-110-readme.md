# MWP-110 README Rewrite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `README.md` with an operator-facing landing page: risk first,
two working quickstarts, links to what exists.

**Architecture:** One file rewritten. The quickstarts are proven by running
them verbatim on a fresh host, not by review.

**Tech Stack:** Markdown, `doctl` for a disposable verification host, the
repository's preflight gates.

## Global Constraints

- No runtime, configuration, deployment, or test behaviour change.
- Do not restate procedures `docs/deployment/*.md` own; link them.
- No migration documentation. v4 is the first public release.
- No placeholder links. If a target does not exist, it is not linked.
- Do not create `SECURITY.md`, `CONTRIBUTING.md`, protocol docs, or privacy
  guidance — MWP-116, MWP-113, MWP-115 own those.
- No internal issue numbers in the public README.
- If a quickstart step cannot be completed from the README alone, fix the
  README rather than supplying outside knowledge.

### Task 1: Rewrite the README

**Files:**

- Modify: `README.md`
- Read: `docs/configuration.md`, `docs/security.md`, `docs/operations.md`,
  `docs/deployment/compose.md`, `docs/deployment/systemd.md`,
  `docs/deployment/images.md`, `.env.compose.example`, `NOTICE`

- [ ] **Step 1: Write the head and the risk section**

Open with one paragraph of what it is, including the single-process,
single-replica scope. Then `## What this does on your behalf`, carrying the
three facts from the design — outbound dialling governed by `TARGET_MODE`,
memory-local sessions, independent browser and upstream hops — each pointing
at `docs/security.md`.

This section must appear before any install command.

- [ ] **Step 2: Write Requirements**

Pinned Bun version read from `.bun-version`, a domain name, ports 80 and 443
reachable. State that port 80 is required for certificate issuance even though
traffic is on 443 — the operations guide records this as the most common
renewal failure.

- [ ] **Step 3: Write the two quickstarts**

Each self-contained and each ending in a working WSS endpoint. Compose first
(portable), systemd second (single VM). Remove the bare `bun dev` path and the
raw `docker run` example from the landing page; `deployment/images.md` keeps
the image details.

- [ ] **Step 4: Write Configuration, Documentation, lineage, and License**

A short table of only the variables an operator must set, linking to
`configuration.md` for the rest. A `Documentation` section linking
configuration, security, operations, and the deployment guides — and nothing
that does not exist. Lineage moved to the bottom, pointing at `NOTICE`.

- [ ] **Step 5: Mechanical checks**

```bash
rg -ni 'pm2' README.md                    # must return nothing
rg -n 'MWP-[0-9]' README.md               # must return nothing
bun -e '
import { existsSync } from "node:fs";
import { dirname, resolve } from "node:path";
const md = await Bun.file("README.md").text();
for (const m of md.matchAll(/\[[^\]]+\]\(([^)]+)\)/g)) {
  const h = m[1];
  if (/^(?:https?:|mailto:|#)/.test(h)) continue;
  const abs = resolve(dirname("README.md"), decodeURIComponent(h.split("#",1)[0]));
  if (!existsSync(abs)) throw new Error(`missing local link ${h}`);
}
console.log("all local links resolve");
'
```

Expected: the first two return nothing; the third prints the success line.

### Task 2: Prove both quickstarts on a fresh host

**Blocked on a disposable host.** Provision one with `doctl`, matching
production's shape (`s-1vcpu-1gb`, nyc3, Ubuntu 26.04). Destroy it afterwards
and confirm the destruction.

A test subdomain must resolve to it before either quickstart can obtain a
certificate; the domain's DNS is not in the DigitalOcean account, so that
record is the operator's to add.

- [ ] **Step 1: Compose quickstart, verbatim**

On a clean host, execute only what the README's Compose section contains. Stop
at the first step that requires knowledge the README does not supply and record
it as a README defect.

Expected: `https://<domain>/health` returns `200` with
`{"status":"healthy","version":…}` over a trusted certificate.

- [ ] **Step 2: systemd quickstart, verbatim**

Same discipline, on a freshly reset host or a second one, so the Compose run
does not leave state that makes the systemd path appear to work.

Expected: the same external `/health` result.

- [ ] **Step 3: Fix every defect the runs exposed, then re-run**

A README that needed a correction is not proven until the corrected version has
been executed from scratch.

- [ ] **Step 4: Destroy the host and confirm**

```bash

```
